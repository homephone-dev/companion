# homephone-companion

A Kotlin Multiplatform + Compose Multiplatform client app for managing a
self-hosted home phone system. This is **Milestone 2** of a two-repo
project:

- **Milestone 1** — [`homephone-dev-server`](../homephone-dev-server) (Go
  backend + Asterisk SIP PBX). Owns every call-allow/block decision and
  exposes a bearer-token-authenticated REST API for devices, contacts
  (allowlist), schedules (quiet hours), and call history. See its
  `docs/api.md` for the exact API contract.
- **Milestone 2** — this repo. A thin client with **no business logic of
  its own**: no allow/block decisions, no local scheduling logic. It only
  reads and writes through the REST API documented in the sibling repo.
  See `CLAUDE.md` for the hard rule on this.

## Stack & versions

Confirmed via web search against JetBrains' own docs/blog as of Aug 2026
(training-data knowledge on this tooling ages fast, so these were checked
rather than assumed):

| Component | Version | Why |
|---|---|---|
| Kotlin | 2.3.20 | Bumped from the originally-scaffolded 2.2.20 during first-build verification: Compose Multiplatform 1.11.0's `components-resources` klib is built with ABI version 2.3.0, which a 2.2.20 compiler cannot consume (`KLIB resolver: Skipping ... incompatible ABI version`). 2.3.20 is the version that actually produced that klib. |
| Compose Multiplatform | 1.11.0 | Current stable JetBrains release (May 2026 blog post); iOS target has been stable since CMP 1.6 in 2025. |
| Ktor | 3.5.2 | Current stable client version referenced in Kotlin docs as of Aug 2026. |
| kotlinx.serialization | 1.9.0 | Paired with Kotlin 2.2.x. |
| kotlinx-coroutines | 1.10.2 | Current stable. |
| kotlinx-datetime | 0.6.2 | Current stable. |
| AGP | 8.7.3 | Current stable AGP compatible with the above; Android is a stub target for now. |
| multiplatform-settings | 1.3.0 | Standard KMP local key-value storage (Preferences on Android, NSUserDefaults on iOS) — used for the backend URL + token, since there is no server-side account/auth layer in this app. |
| iOS deployment target | 17.0 | Reasonable current floor for 2026; adjust in `project.pbxproj` if you need to support older devices. |

Project layout follows the current JetBrains-recommended module naming:
`composeApp` (shared Kotlin/Compose code across all targets, including the
iOS framework source set) + `iosApp` (Xcode wrapper project) + `androidApp`
(thin Android launcher module) — this is the layout produced by the
current [Kotlin Multiplatform wizard](https://kmp.jetbrains.com) and
JetBrains' CMP "New Project" template, rather than the older `shared` +
`androidApp` two-module layout from earlier KMP tooling.

## Building

You'll need, on a real dev machine:

1. **A JetBrains IDE with the Kotlin Multiplatform plugin** (Android
   Studio Ladybug+ with the KMP plugin, or IntelliJ IDEA) to open the
   Gradle project (`settings.gradle.kts` at the repo root), and
2. **Xcode** (current stable, matching iOS 17+ SDK) to open
   `iosApp/iosApp.xcodeproj` for the iOS target.

First-time setup:

```bash
# Generate the Gradle wrapper jar (not committed — none was available
# in the scaffolding environment):
gradle wrapper --gradle-version 8.10

# Then use the wrapper for everything else:
./gradlew build
```

Opening `iosApp/iosApp.xcodeproj` in Xcode and hitting Run will invoke a
Gradle build-phase script (`embedAndSignAppleFrameworkForXcode`) that
compiles `composeApp` into a framework and links it — this is the
standard CMP iOS integration pattern, no CocoaPods involved.

**Before running the app**, open Settings and enter your
`homephone-dev-server` instance's base URL and an API token generated
there — every request needs both.

## Relationship to homephone-dev-server

This repo never re-implements anything the server already decides. If a
feature here would require deciding whether a call should be allowed,
blocked, or scheduled, that logic belongs in `homephone-dev-server`, not
here — see `CLAUDE.md`.
